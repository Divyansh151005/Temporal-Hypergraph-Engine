1. ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------

In large-scale LLM inference (e.g., vLLM, SGLang), GPU VRAM is the primary bottleneck. The Key-Value (KV) cache for extended dialogue histories quickly exhausts high-bandwidth memory (HBM).

This module implements a dynamic, temporal-aware Secondary KV-Cache Storage Tier:
1. Tier 0 (HBM / GPU Memory): Active working context managed via vLLM PagedAttention blocks.
2. Tier 1 (Host RAM / Pinned Memory): High-speed system memory staging area managed by this Rust engine.
3. Tier 2 (NVMe / Storage Engine): Disk-backed temporal hypergraph persistent KV block store.

Key Innovations:
- Temporal KV Eviction: Instead of naive LRU eviction, KV blocks associated with hyperedges whose decay weight w(t) falls below threshold tau are selectively offloaded to Tier 1/Tier 2.
- Content-Addressed Block Deduplication: KV blocks are indexed via BLAKE3 content hashes computed over token IDs and layer embeddings.
- Async Prefetching: When a query matches hyperedges in Set B during bipartite traversal, corresponding KV blocks are asynchronously fetched back to GPU pinned memory before transformer attention layers execute.

--------------------------------------------------------------------------------
2. KV-CACHE BLOCK SPECIFICATION & SERIALIZATION
--------------------------------------------------------------------------------

vLLM allocates KV cache in fixed-size blocks (e.g., block_size = 16 tokens).

2.1 KV Block Layout Parameters
- Number of Layers: L
- Number of Heads: H
- Head Dimension: D
- Block Size (Tokens): B
- Element Precision: FP16 (2 bytes) or BF16 (2 bytes)
- Block Tensor Shape: [2, L, B, H, D]  (where index 0 = Key tensor, 1 = Value tensor)
- Bytes per Block: 2 * L * B * H * D * sizeof(uint16)

For L=32, H=32, D=128, B=16 (e.g., Llama-3-8B):
Bytes per block = 2 * 32 * 16 * 32 * 128 * 2 = 8,388,608 bytes (8 MB per block).

2.2 Block Binary Framing Format

Each offloaded KV block is stored as a contiguous binary blob:

+-------------------+-------------------+-------------------+-------------------+
| Magic Header (4B) | Hash Digest (32B) | Layer Count (2B)  | Head Count (2B)   |
| "V3KV" 0x56334B56 | BLAKE3 Hash       | u16               | u16               |
+-------------------+-------------------+-------------------+-------------------+
| Head Dim (2B)     | Block Size (2B)   | Precision ID (2B) | Payload Len (4B)  |
| u16               | u16               | 1=FP16, 2=BF16    | u32               |
+-------------------+-------------------+-------------------+-------------------+
| Raw Pinned Tensor Byte Stream (Little-Endian FP16/BF16)                       |
+-------------------------------------------------------------------------------+

2.3 Rust Block Struct Definition

```rust

pub struct KvBlockHeader {
    pub magic: [u8; 4],          // b"V3KV"
    pub hash_digest: [u8; 32],   // BLAKE3 Hash

    pub block_size: u16,
    pub precision: u16,          // 1 = FP16, 2 = BF16, 3 = INT8
```

The Python module integrates directly into vLLM's `BlockSpaceManager` and `KVCacheAllocator`.

3.1 Python Abstract Storage Extension Interface

```python
import torch
import numpy as np
from typing import List, Optional, Dict

class HypergraphKVOffloader:
    def __init__(self, rust_engine_handle, device_id: int = 0):
        self.engine = rust_engine_handle
        self.device_id = device_id
        
    def hash_block_tokens(self, token_ids: List[int], parent_hash: Optional[bytes] = None) -> bytes:
        """Computes BLAKE3 deterministic block key from token sequence."""
        import blake3
        hasher = blake3.blake3()
        if parent_hash:
            hasher.update(parent_hash)
        hasher.update(np.array(token_ids, dtype=np.int32).tobytes())
        return hasher.digest()

    def offload_kv_block(
        self, 
        block_hash: bytes, 
        key_tensor: torch.Tensor, 
        value_tensor: torch.Tensor,
        hyperedge_id: str
    ) -> bool:
        """
        Offloads key and value tensors from GPU VRAM -> Host Pinned Memory -> Engine Store.
        Tensors must be contiguous in memory.
        """
        assert key_tensor.is_contiguous()
        assert value_tensor.is_contiguous()
        
        # Concatenate K and V tensors
        kv_combined = torch.stack([key_tensor, value_tensor], dim=0)
        
        # Copy to CPU host pinned memory asynchronously
        cpu_pinned = kv_combined.to("cpu", non_blocking=True)
        torch.cuda.synchronize()
        
        # Pass pointer to Rust storage engine via zero-copy C-FFI
        raw_ptr = cpu_pinned.data_ptr()
        num_bytes = cpu_pinned.numel() * cpu_pinned.element_size()
        
        return self.engine.store_kv_block_raw(block_hash, raw_ptr, num_bytes, hyperedge_id)

    def prefetch_kv_block(self, block_hash: bytes, target_tensor: torch.Tensor) -> bool:
        """
        Asynchronously loads block from Rust Engine into target GPU tensor buffer.
        """
        raw_ptr = target_tensor.data_ptr()
        num_bytes = target_tensor.numel() * target_tensor.element_size()
        
        success = self.engine.load_kv_block_raw(block_hash, raw_ptr, num_bytes)
        return success

```

4. ASYNCHRONOUS PREFETCHING & TEMPORAL EVICTION PIPELINE

---

4.1 Temporal Eviction Protocol

1. Every N execution ticks, the Rust engine queries all active hyperedges in `BipartiteArena`.
2. Computes SIMD time decay w(t) for each edge.
3. If w(t) < tau_offload and edge KV status is IN_GPU_VRAM:
* Send signal to vLLM `BlockSpaceManager.evict_to_secondary(block_id)`.
* Transfer block bytes to engine storage and free vLLM GPU physical block index.


4. Update `TemporalHyperedge` metadata: `kv_offloaded = true`, `block_hash = BLAKE3_HASH`.

4.2 Prefetching Graph Traversal Integration
When user prompt triggers a k-hop temporal search:

1. Engine identifies top-K relevant `TemporalHyperedge` instances based on score S = similarity * w(t).
2. For identified hyperedges, check `block_hash`.
3. If `kv_offloaded == true`, trigger `tokio::spawn` background task to stream KV blocks from engine memory into CUDA host pinned staging buffers.
4. Notify vLLM scheduler that blocks are ready in Tier 1 RAM for instant HBM page swapping (`cudaMemcpyAsync`).
