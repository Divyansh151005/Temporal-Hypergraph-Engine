1. ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------

The Temporal Hypergraph Engine relies on a dual-path IPC/FFI architecture to support both distributed remote environments and high-efficiency local micro-benchmarks:

1. Remote / Distributed Path (gRPC via Tonic):
   - Transport: HTTP/2 over TCP / UNIX Domain Sockets (UDS).
   - Serialization: Protocol Buffers v3 with streaming payloads.
   - Purpose: Multi-tenant SaaS deployments, vLLM secondary storage nodes, and microservice clusters.

2. In-Process / Zero-Copy Path (PyO3 C-FFI Direct Bindings):
   - Transport: Direct C-FFI / Shared Process Memory.
   - Serialization: Zero-copy pointer passing via Rust `PyBuffer` / NumPy pointers.
   - Purpose: Local high-throughput inference (LangChain, vLLM co-located on the same node).

Key Performance Goal:
Eliminate double-serialization overhead when passing dense vector embeddings (e.g., 1536-dimensional `f32` arrays) and KV-cache byte buffers between Python application space and the Rust hypergraph runtime.

3. ZERO-COPY SERIALIZATION & MEMORY PASSING

---

To pass embeddings without string/array parsing overhead:

3.1 Raw Vector Memory Packing

* Floating point arrays (`Vec<f32>`) are transmitted as raw binary bytes (`bytes embedding_raw`) instead of JSON or Protobuf `repeated float`.
* Byte Order: Standard Little-Endian.
* Size Calculation: `byte_length = vector_length * std::mem::size_of::<f32>()`.

3.2 Rust Decoding Snippet (`bytemuck` / Zero-Copy Slice)

```rust
use bytemuck;

pub fn decode_embedding_raw(raw_bytes: &[u8]) -> Result<&[f32], EngineError> {
    if raw_bytes.len() % 4 != 0 {
        return Err(EngineError::InvalidAlignment);
    }
    // Zero-copy cast from u8 slice to f32 slice
    let f32_slice: &[f32] = bytemuck::try_cast_slice(raw_bytes)
        .map_err(|_| EngineError::AlignmentMismatch)?;
    Ok(f32_slice)
}

```

4. PyO3 IN-PROCESS C-FFI BINDINGS

---

For co-located Python environments (e.g., local agent or single-node vLLM instance), bypass gRPC completely using direct PyO3 C-FFI bindings (`maturin`).

4.1 PyO3 Module Interface Specification (`src/lib.rs`)

```rust
use pyo3::prelude::*;
use pyo3::types::PyBytes;
use std::sync::Arc;

#[pyclass]
pub struct NativeHypergraphEngine {
    inner: Arc<ConcurrentHypergraphEngine>,
}

#[pymethods]
impl NativeHypergraphEngine {
    #[new]
    pub fn new(storage_path: &str) -> PyResult<Self> {
        let engine = ConcurrentHypergraphEngine::open(storage_path)
            .map_err(|e| PyErr::new::<pyo3::exceptions::PyRuntimeError, _>(e.to_string()))?;
        Ok(Self { inner: Arc::new(engine) })
    }

    /// Zero-copy insert receiving Python buffer object directly
    pub fn insert_hyperedge_fast(
        &self,
        event_type: &str,
        node_labels: Vec<String>,
        valid_from: i64,
        valid_to: Option<i64>,
        embedding_buffer: &PyBytes
    ) -> PyResult<String> {
        let raw_bytes: &[u8] = embedding_buffer.as_bytes();
        let float_slice = decode_embedding_raw(raw_bytes)
            .map_err(|e| PyErr::new::<pyo3::exceptions::PyValueError, _>(e.to_string()))?;

        let id = self.inner.insert_hyperedge_raw(event_type, &node_labels, valid_from, valid_to, float_slice)
            .map_err(|e| PyErr::new::<pyo3::exceptions::PyRuntimeError, _>(e.to_string()))?;

        Ok(id.to_string())
    }
}

#[pymodule]
fn hypergraph_engine_native(_py: Python, m: &PyModule) -> PyResult<()> {
    m.add_class::<NativeHypergraphEngine>()?;
    Ok(())
}

```

